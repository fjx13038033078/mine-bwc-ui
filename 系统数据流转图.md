## 七、数据一致性保证机制

### 单一数据源 + 响应式设计

```
                  ┌─────────────────────┐
                  │   Pinia Store       │
                  │   (单一数据源)       │
                  │                     │
                  │  devices: [...]     │
                  │  violations: [...]  │
                  │  videos: [...]      │
                  └─────────────────────┘
                           ↓
                    所有数据只能通过
                    Store方法修改
                           ↓
        ┌──────────────────┼──────────────────┐
        ↓                  ↓                   ↓
 ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
 │ 组件A         │   │ 组件B         │   │ 组件C         │
 │ computed(() =>│   │ computed(() =>│   │ computed(() =>│
 │  store.data) │   │  store.data) │   │  store.data) │
 └──────────────┘   └──────────────┘   └──────────────┘
        ↓                  ↓                   ↓
    永远一致           永远一致            永远一致

  ❌ 禁止：直接修改 store.devices[0].status = 'offline'
  ✅ 正确：调用方法 store.updateDevice(id, { status: 'offline' })
  
  ❌ 禁止：创建副本 const localData = ref([...store.devices])
  ✅ 正确：使用computed const localData = computed(() => store.devices)
```

## 八、性能优化策略

### Computed缓存机制

```
┌─────────────────────────────────────────────────────────────────┐
│                      Computed 缓存策略                            │
└─────────────────────────────────────────────────────────────────┘

场景1：频繁访问统计
const violationCount = computed(() => store.violations.length)

第1次访问：计算结果 = 100，缓存结果
第2次访问：store.violations 未变化，直接返回缓存 100
第3次访问：store.violations 未变化，直接返回缓存 100
...
第100次访问：store.violations 未变化，直接返回缓存 100

新增违规：store.violations 变化，computed 自动重新计算 = 101
后续访问：直接返回新缓存 101

性能提升：99次避免了重复计算


场景2：复杂统计计算
const departmentStats = computed(() => {
  // 复杂的统计逻辑，耗时约 10ms
  return store.violations.reduce((stats, v) => {
    // ... 复杂计算
  }, {})
})

无 computed：每次访问都计算 10ms × 100次 = 1000ms
有 computed：只计算一次 10ms，后续99次直接返回缓存
性能提升：99% (1000ms → 10ms)
```

## 九、开发规范速查表

### ✅ 正确做法

| 场景 | 正确做法 | 原因 |
|------|---------|------|
| 读取数据 | `computed(() => store.devices)` | 保持响应性 |
| 修改数据 | `store.updateDevice(id, updates)` | 统一管理 |
| 计算统计 | `computed(() => store.items.length)` | 自动缓存 |
| 监听变化 | `watch(() => store.data, ...)` | 响应更新 |

### ❌ 错误做法

| 场景 | 错误做法 | 后果 |
|------|---------|------|
| 读取数据 | `const list = ref([...store.devices])` | 丢失响应性 |
| 修改数据 | `store.devices[0].status = 'offline'` | 绕过管理 |
| 计算统计 | `const count = store.items.length` | 不会更新 |
| 监听变化 | `setInterval(() => refreshData())` | 浪费资源 |
